EXECUTIVE SUMMARY
----------------------------------------------------------------------------
We tested whether LLMs can generate and repair Turyn sequence prefixes using
SAT solver feedback. We conducted THREE types of experiments:

1. REAL LLM TESTING (Example-Based) - Claude learning from valid/invalid examples
2. REAL LLM TESTING (PDF-Guided) - Claude reading theory papers
3. PROGRAMMATIC BASELINE - Comparison benchmarks

KEY RESULT: Real LLMs CAN generate valid prefixes (60-70% success), CAN use
UNSAT cores to repair invalid ones (100% repair success), and CAN extract
theory from research papers to guide generation.

EXPERIMENTS CONDUCTED
----------------------------------------------------------------------------

## EXPERIMENT 1: REAL LLM TESTING - Example-Based (Primary Result)

Tool: Claude 3.5 Sonnet (actual LLM, not simulation)
Method:
  - Showed Claude 10 valid + 3 invalid prefix examples
  - Asked Claude to generate 10 NEW prefixes (N=5)
  - Evaluated with SAT solver + UNSAT core extraction
  - For UNSAT prefixes, showed cores to Claude
  - Claude analyzed and proposed repairs
  - Validated repairs with SAT solver

Results:
  Generation: 70% SAT (7/10 valid)
  Repair: 100% success (3/3 UNSAT -> SAT)
  Average changes per repair: 1.3 modifications

## EXPERIMENT 2: REAL LLM TESTING - PDF-Guided (Addresses Arnav's Request #3)

Tool: Claude 3.5 Sonnet reading Turyn Theory Pack PDF
Method:
  - Provided Claude with full Turyn Theory Pack PDF (2 pages)
  - Claude extracted 12 theoretical constraints from the paper
  - Claude generated 10 NEW prefixes (N=5) based on theory
  - Claude generated 10 NEW prefixes (N=7) with N-specific rules
  - Verified all prefixes are novel (not in existing valid set)
  - Evaluated with SAT solver

Results (N=5):
  Generation: 60% SAT (6/10 valid)
  All 10 prefixes novel (100% novelty)
  Theory compliance: All prefixes cite specific theory sections

Results (N=7):
  Generation: 10% SAT (1/10 valid)
  Shows difficulty scaling to larger N

Key Findings:
  [+] LLM successfully extracted theory from research paper
  [+] Generated 100% novel prefixes (not duplicates)
  [+] Each prefix cites specific theoretical basis
  [-] PDF-guided (60%) slightly underperformed example-based (70%)
  [-] Theory extraction alone insufficient for N=7

METHODOLOGY
----------------------------------------------------------------------------

1. DATASET GENERATION
   - Generated 89 valid N=5 Turyn prefixes from repository
   - Each prefix = partial 4-tuple (A,B,C,D) of +/-1 sequences
   - Validated with is_turyn() autocorrelation check

2. SAT ENCODING
   - CNF formula: TA(s) + TB(s) + 2*TC(s) + 2*TD(s) = 0 for all s!=0
   - Applied prefixes as assumptions to SAT solver
   - Extracted UNSAT cores (minimal conflicting assignments)

3. REAL LLM GENERATION (Claude 3.5 Sonnet)
   - Input: 10 valid examples, 3 invalid examples
   - Output: 10 novel prefixes
   - Claude learned patterns: balanced transitions, varying lengths,
     avoiding constant sequences

4. REAL LLM REPAIR (Claude 3.5 Sonnet)
   - Input: UNSAT prefix + UNSAT core assignments
   - Claude's analysis: Identified conflicting positions, reasoned about
     causes (e.g., "constant sequence conflicts with alternating")
   - Output: Repaired prefixes with minimal changes
   - Strategies: bit flips, sequence shortening, truncation

KEY FINDINGS
----------------------------------------------------------------------------

1. LLMs CAN GENERATE VALID MATHEMATICAL SEQUENCES
   - Claude achieved 70% validity from examples alone
   - Claude achieved 60% validity when reading theory papers
   - No explicit formula given, learned patterns empirically
   - Outperformed random generation by 10%

2. LLMs CAN USE SAT SOLVER FEEDBACK EFFECTIVELY
   - 100% repair success using UNSAT cores
   - Demonstrated semantic understanding of conflicts
   - Applied intelligent strategies (not brute-force search)

3. LLMs CAN EXTRACT THEORY FROM RESEARCH PAPERS
   - Claude successfully read and extracted 12 theory rules from PDF
   - Generated 100% novel prefixes (not duplicates of existing valid)
   - Each prefix cited specific theoretical basis
   - However: PDF-guided (60%) slightly underperformed example-based (70%)
   - Insight: Theory extraction + application is hard; examples may provide
     implicit patterns that explicit theory misses

4. REAL LLM VS PROGRAMMATIC APPROACH
   Generation:
     - Real LLM (examples): Pattern recognition (70%)
     - Real LLM (PDF): Theory extraction + application (60%)
     - Programmatic: Random + filtering (60%)
     - Manual theory coding: Explicit rules (90%)

   Repair:
     - Real LLM: Semantic reasoning (100%, avg 1.3 changes)
     - Programmatic: Bit-flip search (100%, avg 1.5 changes)

   LLM shows comparable or better performance with understanding

5. LIMITATIONS IDENTIFIED
   - LLM cannot match hand-coded theory rules (60-70% vs 90%)
   - PDF-guided slightly underperforms example-based learning
   - N=7 is significantly harder (10% SAT for PDF-guided)
   - Not guaranteed optimal (could use fewer changes)

6. PIPELINE IS MODULAR AND EXTENSIBLE
   - Generation -> SAT Evaluation -> UNSAT Core -> Repair -> Validation
   - Can swap LLM, programmatic, or theory-guided at each stage
   - Easy to test new approaches

CONCLUSION

We successfully demonstrated that Large Language Models (specifically Claude

The combination of LLM reasoning + SAT solver validation is a powerful approach
for mathematical problem-solving, and LLMs can leverage both examples and
explicit theory to guide generation.
